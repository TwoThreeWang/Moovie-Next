# 浏览器插件

影牛豆瓣助手是一个 Chrome / Edge 插件（Manifest V3），代码在仓库的 `extension/` 目录。它有两个目的：

1. **缓解豆瓣限流。** 服务器只有一个出口 IP，豆瓣一限流，同步标记和补全资料就排不动。插件在用户自己的浏览器里请求豆瓣，每个用户分担一点。
2. **给用户装它的理由。** 同步更及时、不公开的标记也能同步，豆瓣页面上的影牛卡片和角标，豆列导入片单，备份豆瓣标记，追剧提醒。

不上架应用商店（商店不允许插件替开发者在用户浏览器里采集，也不允许"一键播放"这类入口），用压缩包分发：网站的 `/extension` 页面提供下载和安装说明，插件自己检查更新。服务器那边原来的同步和采集保持不变，没装插件的用户（包括所有手机用户）照常用。

## 目录

| 路径 | 内容 |
| --- | --- |
| `extension/src/` | 插件本身。开发时在 Chrome 里"加载已解压的扩展程序"直接选这个目录，连的是本机的 `http://localhost:5200` |
| `extension/src/background.js` | 后台：消息处理、定时任务（每 3 分钟补全资料，每 10 分钟看看要不要自动同步、检查更新、追剧提醒、写回豆瓣） |
| `extension/src/lib/` | 豆瓣请求和节奏（`douban.js`）、影牛接口（`api.js`）、同步和备份（`sync.js`）、补全资料（`tasks.js`）、更新检测、追剧提醒、写回豆瓣（`background-jobs.js`） |
| `extension/src/content/` | 页面上的脚本：豆瓣详情页的卡片（`subject.js`）、海报角标（`badges.js`）、豆列导入（`doulist.js`）、影牛网站上的桥接（`moovie.js`） |
| `extension/embed.go` | 把 `src/` 打包进网站的可执行文件；`Zip` 生成下载用的压缩包 |
| `extension/releases.json` | 插件的发布记录，最新的在前。版本号要和 `src/manifest.json` 一致（有测试检查） |
| `extension/test/` | 插件里不依赖浏览器的逻辑的测试：`node --test extension/test/` |
| `internal/app/extension.go` | 下载页、连接页和插件调用的 `/api/ext/` 接口 |
| `internal/extapi/` | 插件相关的表：连接凭证、贡献记录、写回豆瓣的待办 |

## 下载和更新

`/extension/download` 现场打包 `src/`，把里面写死的开发地址 `http://localhost:5200` 换成 `SITE_URL` 的协议和域名（清单里的 host_permissions、内容脚本的 matches、`config.js`）。压缩包里的目录名固定是 `moovie-extension`，不带版本号：更新时解压覆盖原来的文件夹，在扩展程序页点"重新加载"，设置和连接都还在（浏览器按目录路径认插件，路径不变 ID 就不变）。

插件每 12 小时调一次 `/api/ext/version`（不需要登录），版本比自己新时图标上显示"新"，并且每个新版本弹一次通知，点开是 `/extension#update`。

**发布新版本**：改 `extension/src/manifest.json` 的 `version`，在 `extension/releases.json` 最前面加一条（版本、日期、更新内容），随网站一起部署。

## 连接账号

插件不用网站的登录 Cookie，也不过 CSRF 校验：

1. 用户在插件里点"连接影牛账号"（第一次安装时自动打开），到 `/extension/connect`，点"允许连接"。
2. 服务器签发一个随机凭证（`mvx_` 开头），只把哈希存进 `extension_tokens`，明文放在这次回应的页面里（`Cache-Control: no-store`）。
3. 插件在本站页面上的脚本读走凭证交给后台，后台用它调 `/api/ext/me` 确认，存进 `chrome.storage.local`。重新连接时先吊销旧凭证。

之后每次请求放在 `Authorization: Bearer` 头里。凭证记着签发时账号的密码版本，改密码、被封禁后失效；插件里"断开连接"、设置页"断开全部插件"会删掉它；90 天没用过的每天清理一次。

插件装了的话，会在本站页面的 `<html>` 上写 `data-moovie-ext="版本号"`，设置页和下载页据此显示"已装插件"。

`/api/ext/` 回应里的链接都是站内路径（`/m/12`、`/play/12`），插件用自己连着的网站地址拼成完整链接，不用服务器的 `SITE_URL`：两者不是同一个站时（比如本机开发时 `.env` 里填的是正式域名），作品编号会对到别的站的别的作品上。

## 同步豆瓣标记

插件从这个浏览器的 `dbcl2` Cookie 认出登录着的豆瓣账号，用登录状态请求手机版的标记列表接口（`m.douban.com/rexxar/api/v2/user/<id>/interests`），把豆瓣的原始回答一页一页交给 `/api/ext/douban/interests`。服务器用和自己同步时相同的代码解析（`providers.DecodeInterests`）和导入（`doubansync.ImportPage`），规则不变：本站已有的标记不覆盖，只有"想看"会升级成"看过"。

- 增量：读到一整页都已经导入过就停；第一次、换了豆瓣账号、上次有失败的，完整读一遍。
- 插件里登录的豆瓣账号和影牛上绑定的不一样时，自动改绑（`BindFromExtension`），不要求标记公开。
- 完整同步一次、没有失败的，服务器记下 `users.douban_ext_synced_at`。三天内服务器每天的自动同步跳过这个用户；插件卸载了，三天后服务器自动接手。
- 设置页的豆瓣同步：没连接插件时提醒"不装插件时由服务器替你去豆瓣读取，豆瓣经常限流，同步可能不及时，甚至失败"，并给出安装入口。

## 补全作品资料

插件向 `/api/ext/tasks` 领任务：先是这个用户自己标记的、自己片单里的、还没有豆瓣资料的作品；打开"也帮影牛补全别的作品"（默认打开）时，再从服务器排着的 `media.refresh` 任务里借一些（`jobs.Queue.Lend`，有人正等着的不借）。领走的任务服务器推迟 10 分钟，插件交回来就删掉（`ingest.ApplyContributed`），没交回来服务器到时间照常做。

插件不带 Cookie 请求详情接口（`m.douban.com/rexxar/api/v2/movie|tv/<id>`），把原始回答交给 `/api/ext/douban/subject`，服务器用 `providers.DecodeSubject` 解析。另外两条来源：

- 影牛作品页显示"资料获取中"时，横幅上带着豆瓣 ID，插件马上去取（`urgent`，后面补充资料的步骤也优先）。
- 用户打开豆瓣详情页、影牛这部作品缺资料或 7 天没同步时，插件把页面上片名、海报、信息栏、评分、简介、结构化数据几块摘出来交给 `/api/ext/douban/page`，服务器用 `providers.ParseSubjectPage` 解析。不额外访问豆瓣，不带页面上的账号信息。

**防假资料。** 交上来的都是用户控制的内容，服务器写入前检查：条目编号对得上；长度、数量、年份、评分在合理范围；海报只能是 `*.doubanio.com`；已有完整资料的作品，片名（或原名）要对得上、年份最多差一年，否则不采用。插件说"豆瓣上没有"时只报告，不把作品标成 not_found（否则任何人都能让作品消失）。每个账号每天最多交 1500 部。每次采用都记进 `media_contributions`，主页按补全数量显示称号（`extapi.TierFor`：1 部拾片人、50 场记、200 资料员、1000 档案官、5000 片库守护者、20000 影史编修），`/contributors` 贡献榜列出补全最多的前 50 名（只列公开了主页的人，点名字进主页），有人交假资料时可以按人找出他碰过的作品。

## 豆瓣请求的节奏

插件里三条通道各管各的（`lib/douban.js`）：

| 通道 | 用途 | 间隔 | 被拒绝后 |
| --- | --- | --- | --- |
| own | 带登录状态读自己的标记（同步、备份） | 1.5 秒起 | 暂停 30 分钟 |
| anon | 不带 Cookie 取详情（补全资料） | 7 秒起，每天最多 300 部 | 暂停 6 小时 |
| write | 写回豆瓣（实验） | 3 秒起 | 暂停 1 小时 |

间隔带 0~50% 的随机抖动，偶尔多歇一会儿。和服务器一样，单个条目的 403 不算限流：同一条通道在上一次成功之后接连有几个不同的对象被拒绝（403/418/429、跳到验证页、该是数据的地方给了网页）才暂停。插件不碰验证码。

豆瓣手机版接口没有 Referer 会返回 400。插件用会话级的 declarativeNetRequest 规则给自己后台发出的豆瓣请求（`tabIds: [-1]`）加 Referer，用户在网页上浏览豆瓣不受影响。

## 豆瓣页面上的功能

- **影牛卡片**（`movie.douban.com/subject/<id>/` 右侧栏顶部）：你在影牛的标记、看到第几集、TMDB 评分、收录它的片单、相似推荐；"去影牛播放""影牛详情"；"想看""看过"直接在影牛标记（`/api/ext/mark`，本站没有的先收录，已有的评分和短评保留）。影牛没收录时显示"收录到影牛"。
- **海报角标**（`movie.douban.com`、豆列、搜索、个人页）：批量查 `/api/ext/marks`，在海报左上角标"想看""看过""看到第 N 集"。只认 40px 以上的图片，片名旁的小图标不算。页面动态加载的海报过 0.8 秒也会标上。
- **豆列导入**（`www.douban.com/doulist/<id>/`）：从第一页读起（每页之间歇 1~2 秒），最多 200 部影视条目，`/api/ext/collections` 建成私密片单草稿，打开编辑页。

## 其他功能

- **备份**：设置页读出全部"看过、在看、想看"（含评分、短评、标签、时间），下载成 JSON 或 CSV（带 BOM，Excel 能直接打开；公式开头的格子加 `'`）。
- **追剧提醒**：每 3 小时取 `/api/ext/airing`（想看的、或有播放进度的剧，最近 60 天有更新的，播出到第几集），和上次看到的比，变大了弹通知。第一次只记录。
- **写回豆瓣（实验，默认关闭）**：本站的"想看""看过"在 `douban_outbox` 记一条（只记连接过插件的用户，保留 30 天）。插件打开这个功能时从当前位置开始，之后每 10 分钟取新的，用豆瓣网页按钮的接口（`movie.douban.com/j/subject/<id>/interest`，带 `ck`）写到豆瓣。不写短评，不删除豆瓣上的标记。这个接口没有在真实账号上验证过，失败时停下并在弹窗里显示原因。

## 测试

- `go test ./extension/ ./internal/app/ -run Extension`：打包、清单引用的文件、版本号；连接、凭证失效、导入标记、领任务和借任务、采用和拒绝资料、卡片、角标、追剧、写回待办、豆列导入、下载页。
- `node --test extension/test/`：版本号比较、CSV、详情接口先电影后剧集、接连被拒绝后暂停。
- 在 Chrome for Testing 里加载 `extension/src` 实际跑过：连接账号、弹窗和设置页、"资料获取中"由插件取回并刷新、豆瓣详情页的卡片和"想看"按钮、豆列导入 200 部、豆列页的角标。**需要豆瓣登录的部分（同步、备份、写回豆瓣）没有用真实豆瓣账号跑过。**
