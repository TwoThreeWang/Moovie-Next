# 作品资料：采集与榜单

作品资料以豆瓣为主，TMDB、IMDb、Wikidata 补充；AI 写语义描述并算向量，用于相似推荐。

## 采集流程

### 什么时候采集

| 入口 | 什么情况下 | 优先级（越大越先做） |
| --- | --- | --- |
| 打开详情页 | 这部作品还没从豆瓣同步过。已经排在队尾的会被提到最前面 | 20 |
| 管理员 | 按豆瓣 ID 添加作品，或者点"刷新"。不管冷却期，四步整条重跑 | 10 |
| 热门榜单 | 每 6 小时刷新一次，榜单里新出现的作品 | 5 |
| 站内搜索 | 作品库里不到 3 个结果时，去豆瓣查联想（同一个词一天一次），查到的新作品 | 5 |
| 本地播放 | 从搜索页"我的源"点进作品库里没有的作品、播放源带了豆瓣 ID，开始播放后（`POST /api/media/discover`，每个账号每分钟最多 20 个）。搜索时的片名匹配只读，不收录 | 5 |
| 导入豆瓣标记 | 用户点"同步"是完整同步（优先级 5）；每天自动的那次是增量同步（-2），读到整页都已导入就停 | — |
| 导入带来的新作品 | 列表里已经有片名、海报和评分，晚点补全不影响使用 | 0 |
| 每小时巡检 | 四步里漏掉的都补上（见下） | -1 / -2 |

### 一部作品的四步

每一步是一个单独的任务，成功了马上保存、再排下一步；失败了只重试这一步，不会让前面的步骤重来。

1. **豆瓣**（`media.refresh`）：片名、年份、简介、类型、地区、导演、主演、评分、海报、又名。已知是电影还是剧集时先试对应的接口，猜对了只发一次请求。豆瓣确认没有这个条目（两个接口都是 404）就记成 `not_found` 并隐藏，以后从任何入口送来都不再请求。
2. **Wikidata、TMDB**（`media.enrich`）：Wikidata 按豆瓣 ID 精确对应，给出 IMDb、TMDB 编号和各语言片名；TMDB 给剧照、分集、连载状态，豆瓣没有的简介、原名、片长也用它的。找 TMDB 条目的顺序：已存的编号 → 用 IMDb 编号反查 → 片名加年份搜索。
3. **AI 写语义描述**（`media.semantic`）：把资料发给大模型（OpenAI 格式的 `/chat/completions`），写成一段 200 字以内、语义密度很高的描述，保存到 `semantic_text`。提示词和资料格式固定（`internal/ingest/prompt.go`、`media.SemanticInput`），导入的历史描述也是按这个格式写的，不必重新生成。`semantic_hash` 记着写描述时所用资料的哈希：资料没变就不再调用 AI。
4. **算向量**（`media.embed`）：用语义描述算 768 维向量（OpenAI 格式的 `/embeddings`，默认模型 `quentinz/bge-base-zh-v1.5`）。描述改写了，旧向量随之清空重算。

描述和向量分开保存：AI 成功、向量失败时，描述留着，重试向量不会再调用一次 AI。没配 AI 时不写描述，新作品也就没有向量，相似推荐改按类型重合度。

### 失败了怎么办

- 重试间隔逐次加长：1 分钟、10 分钟、1 小时、6 小时、1 天，共 6 次（约 31 小时）。用完标记为失败。
- **冷却期**：失败记录保留 14 天，这期间这部作品的这一步不会再被任何入口排进来（管理员手动刷新除外），一个一直出错的作品不会被反复送去请求对方。成功一次就清掉失败记录。
- Wikidata 或 TMDB 出错只算第 2 步失败，豆瓣不会再被请求；重试用完时照样往下写描述，过了冷却期由巡检再补一次。
- 豆瓣限流（403 / 418 / 429）：任务放回队列一分钟后再做，不算失败；连续被限流时整条豆瓣通道暂停 10 分钟，任务原样等着。入队超过 3 天的任务再被限流就按普通失败算，免得某个条目一直被拒绝、永远在队列里转。

### 巡检挑哪些作品

- 第 1 步：从没同步成功过的；连载中的剧集每天一次（TMDB 标了连载中，或者没标状态但是近两年的）；近两年上映的每周一次（评分还在变）。更早的同步一次就够了。
- 第 2 步：豆瓣同步过、这一轮还没补到 Wikidata / TMDB 资料的。
- 第 3 步：资料够了（有片名和简介或原名）、还没有语义描述的。正在补第 2 步的先不挑，免得 AI 按不全的资料写一遍、补完又写一遍。
- 第 4 步：有描述、没向量的。
- 正在排队、运行或处在冷却期的作品都不挑，一批一直失败的作品不会每次都排在最前面、把别的挤掉。

### 豆瓣 ID 的过滤

- 格式：7–9 位数字，不以 0 开头（豆瓣的条目编号从 100 万开始）。不合格式的不收录，也就不会拿去请求。
- 豆瓣确认没有的 ID（比如图书、音乐的条目）永久记住，不再请求。
- 一直出错的 ID：6 次重试用完后冷却 14 天。

### 执行通道

- 豆瓣通道：3 个执行位，所有豆瓣请求共用每秒一次的限速。补豆瓣资料、刷新榜单、同步用户标记都走这里。
- AI 通道：2 个执行位。写一段描述要十几秒到一分钟，不让它堵住别的任务。
- 红果通道：2 个执行位，共用每秒一次的限速，只做短剧的任务（见"短剧"）。
- 默认通道（`WORKER_CONCURRENCY`，默认 2）：Wikidata / TMDB、算向量、巡检、清理。

后台概览显示还有多少作品在等、最早的等了多久、照现在的速度大约多久做完。完成的任务记录保留 3 天。重启不会把周期任务（榜单、巡检、每日同步）立刻再跑一遍。

## 豆瓣请求节奏

豆瓣请求之间默认间隔 1 秒。返回 403 / 418 / 429（被限流）时间隔翻倍，最多 1 分钟；连续 3 次被限流就整体暂停 10 分钟，暂停期间的请求直接失败，任务稍后自动重试，页面不会卡住；之后每成功一次，间隔缩回一点。后台概览显示当前的节奏。需要时可以用 `DOUBAN_PROXY`（http / https / socks5）让豆瓣的接口请求走指定的出站代理。

想用买的 Clash 订阅：网站本身不认识 Shadowsocks、VMess、Trojan 这些协议，所以另外跑一个 mihomo（Clash.Meta 内核）容器，把订阅变成一个 HTTP / SOCKS5 代理，再把 `DOUBAN_PROXY` 指过去。仓库里不带 mihomo 的配置，需要自己部署，建议：

- 单独的容器、单独的 Docker 网络：不用 host 网络、不建 TUN 网卡、不要额外权限，不向宿主机开放端口，宿主机的网络不受影响。
- mihomo 放在 `mihomo_default` 网络里（`docker-compose.yml` 已让网站和 worker 加入这个网络），在 `.env` 里填 `DOUBAN_PROXY=http://mihomo:7890`；mihomo 只接受 Docker 内网的连接，也可以再加用户名密码。
- 节点放在一个轮询的负载均衡组里，连续的请求从不同的节点出去；健康检查用通用地址，不额外打扰豆瓣。填了订阅链接的配置文件不要提交到仓库。

## 热门榜

首页和发现页的电影、剧集、综艺、动漫四个榜，每 6 小时重新生成一次，结果整批写进 `chart_items`。每一类综合三个来源，每部作品的分数 = Σ 权重 ÷ (20 + 名次)：

| 来源 | 权重 | 说明 |
| --- | --- | --- |
| 豆瓣热门 | 0.5 | 电影：热门电影；剧集：国产剧和美剧交替合并；综艺、动漫：各自的榜单。最贴近国内观众，作为主体 |
| TMDB 一周趋势 | 0.2 | 只分电影和剧集两个榜，剧集趋势里的作品按作品库里的类型分到剧集、综艺、动漫。只算作品库里已有的（按 `tmdb_id` 对应，一部剧取最新一季），不会因此去请求豆瓣 |
| 本站热播 | 0.3 | 最近 7 天看的人数（`playback_positions`，同一个人看多少集都只算一次）。最近 7 天看过东西的人少于 20 时不计入，免得两三个人就能把一部片子顶上榜 |

- 只用名次，不用各家的评分或热度值：那些数没法放在一起比。"20 + 名次"让前几名之间拉开差距，又不会让单一来源的第一名压过同时出现在几个来源里的作品。
- 每个榜取前 50 部。某一类的豆瓣榜取不到时这一类保持原样；TMDB 取不到就这次不算它。
- IMDb 没有免费的热门接口，只用来对应作品，不作为热度来源。

## 热搜榜

`/trends`，有"今天"（最近 24 小时）和"本周"（最近 7 天）两个榜；搜索页显示本周前 10 名。

- **怎么记**：用户在搜索页停下来 1.5 秒、作品库里有结果，浏览器才上报一次（`POST /api/search-log`，每个 IP 每分钟最多 30 次）。同一个人（登录用户按账号，游客按 IP）10 分钟内同一个词只算一次。
- **怎么存**：`search_counts` 每天每个词一行（日期、规范化的词、显示用的写法、次数），不存是谁搜的，也不保存每一次搜索，所以行数取决于每天有多少个不同的词，和搜索次数无关。计数先在内存里累加，每分钟用一条语句批量写入（已有的词加上新的次数）；服务停下时再写一次。保留 31 天（后台概览要画 30 天的搜索趋势）。
- **怎么排**：同一个词的不同写法合并计数，显示最近一天里的写法。库里只有按天的计数，"最近 24 小时"用滑动窗口近似：今天的全部 + 昨天的数 ×（今天还没过去的比例），"本周"同理。至少 2 次才上榜，命中屏蔽词的不上榜。和上一个同样长度的时间段比：以前没有的标"新上榜"，次数达到上次的 1.5 倍以上标"上升"。热度条按榜首的比例画。
