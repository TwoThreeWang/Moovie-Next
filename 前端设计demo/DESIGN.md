# Moovie · 新界面设计方案（tvui-lab）v2

> 实验目录，只放原型。技术约束：原生 HTML + HTMX + JS + CSS，无构建步骤；以后可以直接套到 Go Template 上，复用现有 `/api/htmx/*` 端点。
>
> **v2 调整**：主要用户在手机上，其次是电脑。方案改为**手机优先、速度优先**。Apple TV 的东西只保留它的质感（以内容为主、只有一个焦点、氛围色、沉浸式播放），遥控器式交互降级为桌面端的增强。
>
> **v3 调整**：**一套页面、一套 HTML、完全自适应**。不做“手机版 / 电脑版”两套，不按设备 UA 分流；布局随可用宽度连续变化，交互随输入方式（触屏 / 鼠标 / 键盘）自动切换。见 §2.5。

## 0. 现有功能盘点（按用户心智归类）

| 用户心智 | 现有能力 | 现有入口 |
| --- | --- | --- |
| **我接着看** | 继续观看（本地+云同步）、今日更新、下一集播出日期 | `/api/htmx/history/recent`、`/today-updates`、`/watch-schedule` |
| **我想找一部** | 统一搜索、联想、趋势、发现（按类型）、IPTV | `/search`、`/api/v2/media/suggest`、`/trends`、`/discover/:type`、`/iptv` |
| **给我推荐** | 为你推荐、相似内容（带理由）、热门快照、公开片单 | `/foryou`、`/similar-with-reason/:id`、`/list` |
| **这部怎么样** | 详情、剧照、季/集、短评/长评、想看/看过 | `/movie/:id`、`/movie-backdrops`、`/movie-series`、`/reviews` |
| **开始播放** | 多源聚合、换源、故障切换、倍速、画中画、弹幕、广告跳过、进度同步 | `/watch/:douban_id`、`/playback-candidates`、`/api/danmaku` |
| **我和朋友** | 片场、关注、通知、点赞回复、公开主页、月报分享 | `/cinema`、`/feed`、`/notifications`、`/user/:id` |
| **我的** | 想看/看过/历史、豆瓣同步、设置、反馈 | `/dashboard`、`/dashboard/settings` |

现在的问题：几十个页面平铺，每个功能占一页（“网站思维”）。目标改成“内容思维”：用户只在**浏览 → 了解 → 观看**三种状态之间切换，其余能力放进这三种状态里。

### 现状的速度问题（实测文件体积）

| 资源 | 体积 | 问题 |
| --- | --- | --- |
| `style.css` | 143KB（gzip 26KB） | 所有页面共用一个文件，首屏只用到一小部分，而且会阻塞渲染 |
| 播放页依赖 | artplayer + hls.js（约 620KB）+ flv + 弹幕插件 + `player.js` 58KB | iOS Safari 原生就支持 HLS，这些对 iOS 用户基本白下载 |
| 首页“继续观看” | 从 localStorage 由 JS 渲染 | 先显示 loading，再出内容，会造成布局跳动（CLS） |
| 图片代理 | 原图透传，没有尺寸参数 | 手机上 2.5 列小卡也会下载大图 |
| 第三方脚本 | gtag 和广告脚本在 `<head>` | 和首屏争抢带宽和主线程 |

## 1. 性能预算（硬指标，原型阶段就用 Lighthouse 移动端节流来验）

| 指标 | 目标（中端安卓 + 4G 节流） |
| --- | --- |
| LCP | < 1.8s |
| INP | < 150ms |
| CLS | < 0.03 |
| 首页首次加载传输量（不含图片） | < 60KB |
| 关键 CSS（内联） | < 12KB 未压缩，第一个 TCP 往返就能画出首屏 |
| 自有 JS | < 8KB gzip，全部 `defer`，首屏不依赖 JS |
| 二次访问 | 由 Service Worker 外壳缓存，导航时接近 0 RTT |

**原则：首屏内容由服务端直接渲染出来，JS 只做增强。JS 挂了页面照样能看、能点、能播。**

## 2. 设计原则（手机优先）

1. **拇指区优先**。主要操作放在屏幕下方 1/3：底部 Tab 栏、详情页底部吸附的“播放”大按钮、操作菜单用底部弹出面板（bottom sheet）。
2. **内容即界面**。海报和剧照是主角，UI 尽量少；颜色取自作品主色（由服务端预先计算，见 §5）。
3. **横滑交给 CSS**。横向内容行用 `overflow-x: auto` + `scroll-snap`，零 JS、原生惯性；手机上露出半张卡，提示“还能往右滑”。
4. **触屏不依赖悬停**。所有悬停效果只在 `@media (hover:hover) and (pointer:fine)` 下生效；长按卡片弹出操作面板（想看 / 看过 / 移除记录）。
5. **一套组件，连续自适应**。同一份 HTML 从 320px 手机一直撑到 2560px 大屏，密度、列数、字号随宽度平滑变化；悬停、视差、键盘导航按输入能力自动开启，和屏幕尺寸无关（触屏笔记本、接了键盘的 iPad 也能正确工作）。
6. **材质要克制**。毛玻璃（`backdrop-filter`）在低端安卓上很耗 GPU，所以只用在**固定位置的两处**：底部 Tab 栏和播放器面板。其余浮层用不透明的深色。`@supports` 不支持时退回纯色。
7. **动效便宜**。只动 `transform` 和 `opacity`；用弹簧曲线 `cubic-bezier(.2,.8,.2,1)`；尊重 `prefers-reduced-motion`；页面切换用 View Transitions 渐进增强，不支持的浏览器直接切。

## 2.5 自适应策略

**原则：内容尺寸驱动布局，而不是设备驱动布局。** 能用流式计算就不写断点，必须写断点的地方只有 3 个。

**① 流式尺度（不写断点）**
- 字号、间距、圆角全部用 `clamp()`：例如 `--fs-hero: clamp(28px, 4vw + 12px, 72px)`、`--gutter: clamp(16px, 4vw, 64px)`。
- 内容行的卡片宽度：`--card-w: clamp(112px, 28vw, 220px)`。手机上一屏约 3.3 张（露半张提示可滑），电脑上 6～8 张，中间宽度连续过渡。
- 网格页（发现、片单、搜索结果）：`grid-template-columns: repeat(auto-fill, minmax(var(--card-w), 1fr))`，列数自然增减。

**② 组件级自适应（Container Queries）**
- 卡片、Hero、详情头部、剧集卡用 `@container` 按**自身所在容器**的宽度变化，而不是按屏幕：同一张剧集卡，在详情页主栏是横排（缩略图 + 集名 + 简介），在窄侧栏里自动变成竖排。
- 这样组件可以放到任何位置复用，不需要为每个页面写一套样式。

**③ 只有 3 个布局断点（只管页面骨架）**

| 可用宽度 | 导航 | 详情页 | 播放页 |
| --- | --- | --- | --- |
| < 720px | 底部 Tab 栏（含安全区） | 单栏，竖版剧照首屏，播放按钮吸底 | 视频在上，选集/简介在下 |
| 720–1199px | 左侧图标导航栏（Rail） | 单栏，横版剧照首屏，按钮回到首屏内 | 同上，视频更大 |
| ≥ 1200px | 顶部导航栏（半透明，滚动后加深） | 两栏：左信息 / 右剧照与选集 | 视频 + 右侧选集/弹幕侧栏，可切剧场模式 |

同一份 HTML，导航用同一个 `<nav>` 元素，只靠 CSS 改变位置和形态，不重复输出。

**④ 输入能力自适应（与宽度无关）**

| 条件 | 开启的交互 |
| --- | --- |
| `(hover:hover) and (pointer:fine)` | 悬停放大、视差高光、悬停预取、Hero 悬停暂停 |
| `(pointer:coarse)` | 触控热区 ≥ 44px、长按菜单、播放器手势、touchstart 预取 |
| 首次按下方向键 / Tab 键 | 加载 `focus.js`：空间导航 + 清晰的焦点环（Apple TV 式焦点体验） |
| `prefers-reduced-motion` | 关闭视差、自动轮播、页面过渡 |

**⑤ 图片自适应**
- 所有图片用 `srcset` + `sizes`，`sizes` 直接写成和 `--card-w` 一致的表达式，让浏览器按实际显示宽度和 DPR 选 s/m/l 尺寸。
- Hero 用 `<picture>`：窄屏给竖版（4:5）构图，宽屏给横版（16:9）剧照，媒体条件和布局断点一致，确保只下载一张。

**⑥ 验收宽度**：320 / 375 / 414 / 768 / 1024 / 1280 / 1440 / 1920，外加横屏手机（844×390）和 iPad 分屏（约 507px）。任何宽度下都不出现横向滚动条，也不出现突兀的跳变。

## 3. 信息架构

导航固定 4 个入口，形态随宽度变化（底部 Tab → 侧边 Rail → 顶部导航，见 §2.5），入口内容完全相同。

```
首页 ─┬─ Hero（单张；手机上是 4:5 竖版剧照，电脑上是 16:9；只有第一张图是 fetchpriority=high）
      ├─ 继续观看（服务端渲染云端记录；未登录时由 JS 读 localStorage，提前留好占位高度，不跳动）
      ├─ 今日更新（在追剧集，带“新”角标）
      ├─ 因为你看过《X》
      ├─ 热门电影 / 热门剧集
      ├─ 精选片单
      └─ 朋友在看（片场）
      ※ 第二行以后用 hx-trigger="revealed" 懒加载，首屏 HTML 只包含 Hero 和第一行

发现 ─ 顶部分段：电影 / 剧集 / 综艺 / 动漫 + 类型标签（横滑），下面是网格；“趋势”作为一个固定标签
搜索 ─ 点一下 Tab 就聚焦输入框、弹出键盘；空状态显示最近搜索和趋势；联想结果直接显示为海报网格
我的 ─ 头像卡 + 月报入口 ／ 想看 · 看过 · 历史（分段）／ 通知 ／ 设置 · 豆瓣同步 · 反馈
```

详情页和播放页不占 Tab，是从卡片“推”进来的层级。

## 4. 关键页面

### 4.1 详情页（手机）
- 首屏：竖版剧照铺满上半屏，往下渐变到背景色；叠一层标题、一行元信息（年份 · 类型 · 时长 · 豆瓣分）。
- **底部吸附操作栏**（拇指区）：主按钮 `▶ 播放` / `继续 S2E5 · 剩 18 分` / `下一集`，旁边是 `＋想看`、`⋯`。
- 往下依次是：简介（默认 3 行，可展开）→ 选集（季分段 + 横滑集卡，已看的打勾，末尾一张“下集 11/12 更新”卡）→ 剧照 → 演职员 → 短评 → 相似。每一段都 `revealed` 懒加载。
- 选源对普通用户隐藏：默认自动选最佳源；`⋯` → “切换来源”打开底部弹出面板。

### 4.2 播放器（手机）
- 点播放后直接进入原生全屏并锁定横屏（`screen.orientation.lock`，iOS 用 `webkitEnterFullscreen`）。
- 手势：
  - 双击左/右半屏：快退/快进 10 秒；
  - 横向拖动：拖进度，并显示时间气泡；
  - 竖向滑动右半屏：调亮度（用遮罩模拟）。音量交给系统键，iOS 不允许网页改音量。
- 控件 3 秒不操作就隐藏；底部面板分 选集 / 倍速 / 弹幕 / 来源 几项，只有这里用毛玻璃。
- “跳过广告/片头”胶囊按钮、结束前 20 秒的“下一集”倒计时卡。
- **按需加载**：iOS 和 Safari 用原生 `<video>` 播放 HLS，不加载 hls.js；只有需要 MSE 的浏览器才动态 `import` hls.js；FLV 和弹幕插件等真正用到时再加载。自研一个轻量控制层（约 6KB）替代 artplayer。

### 4.3 宽屏与鼠标键盘下的变化（同一页面，自动生效）
- ≥ 1200px：Hero 变成 16:9 轮播（8 秒切换，悬停暂停）；详情页变两栏，播放按钮回到首屏内，不再吸底。
- 有精确指针时：卡片悬停放大 1.06、视差高光（只写 CSS 变量，不碰布局）。
- 用键盘时：方向键空间导航、`/` 唤起搜索、空格播放/暂停、`F` 全屏、`←/→` 跳 10 秒。

## 5. 速度方案

**首屏**
- 关键 CSS 内联到 `<head>`；其余样式按页面拆分（`home.css` / `detail.css` / `player.css`），用 `media="print" onload` 的方式异步加载。
- 不用 Web 字体，直接用系统字体栈 `-apple-system, "PingFang SC", "Noto Sans SC", system-ui`。
- 所有图片都写死 `width/height` 或 `aspect-ratio`，避免布局跳动；Hero 用 `fetchpriority="high"`，其余用 `loading="lazy" decoding="async"`。
- 屏幕外的内容行加 `content-visibility: auto`，减少首屏的布局和绘制开销。
- 统计和广告脚本推迟到 `load` 之后的空闲时间（`requestIdleCallback`）再加载。

**图片（收益最大）**
- 豆瓣图片本身提供多种尺寸（`s_ratio_poster` / `m_ratio_poster` / `l`），而且已经是 webp。卡片用 s/m，详情页用 l，配合 `srcset`。
- 后端后续改进（不在原型范围内）：图片代理支持 `?w=`，缩放并转 AVIF/WebP；剧照入库时预先算出**主色**和一个 **16 字节的模糊占位色**，模板里直接输出 `style="--c:#3a2a1f"`。氛围色因此零成本，不再需要客户端用 canvas 取色（canvas 取色还会遇到跨域问题）。

**导航**
- ~~`hx-boost` 全站开启~~ → **原型实际采用：普通页面跳转 + Speculation Rules 预渲染 + 跨文档 View Transitions + bfcache**。原因：hx-boost 不会合并 `<head>`，按页拆分的 CSS 会丢失；而预渲染后的普通跳转本身就接近瞬开，返回还能直接命中 bfcache。HTMX 只用在懒加载内容行、季切换、想看/看过这类局部更新上。
- 预取：手指按下（`touchstart`）或鼠标悬停 65ms 时就预取目标页；Chrome 额外用 Speculation Rules 预渲染第一屏卡片的详情页。
- Service Worker：外壳（CSS、JS、图标）走 cache-first，HTML 走 stale-while-revalidate，海报走 cache-first 并限制条目数（LRU）。
- 不注册 `unload` 事件，保证能进 bfcache，返回秒开。

**交互流畅度（INP）**
- 长列表不用 JS 虚拟滚动，靠 `content-visibility` 加分页 `revealed`。
- 滚动和触摸监听全部 `passive`；视差用 `requestAnimationFrame` 合并更新。

## 7. 落地节奏

1. **原型**：首页、详情、播放三页，一次写成自适应的，按 §2.5 ⑥ 的宽度逐个检查；每页都跑一遍 Lighthouse 移动端节流，达到 §1 的指标。
2. **对齐数据**：把假数据换成现有模板变量，做成 `layouts/v2.html`，通过 cookie 灰度。
3. **后端配合**：图片代理支持缩放、主色预先计算、“继续观看”改由服务端渲染。
4. **逐页替换**：首页 → 详情 → 播放 → 搜索/发现 → 我的；旧页面保留作降级。
